# AutoJs6 Plugin Bun Runtime Repository Guide

This repository contains the standalone Bun Runtime plugin for AutoJs6. Keep every implementation, contract, resource, test, and document aligned with the facts below.

## Repository identity

- Project directory: `AutoJs6-Plugin-Bun-Runtime`
- Gradle root name: `autojs6-plugin-bun-runtime`
- Application name: `Bun Runtime`, always English and non-translatable
- Application ID: `io.github.supermonster003.autojs6.plugin.bun.runtime`
- Plugin ID: `bun-runtime`
- Engine: `bun`
- Variant: `bun-1.4.0-android`
- Runtime service action: `org.autojs.plugin.bun.RUNTIME`
- Runtime service category: `bun`
- Capability API: `bun-runtime-api`
- Minimum host build: `5278`

Do not add compatibility aliases for unpublished names or identifiers. Update the AutoJs6 host and the shared API contract together when an identity or protocol value changes.

- The runtime is the official Bun `bun-v1.4.0` Android release at commit `34cbb9a40b4bd1bd767d134a7065e66c2432a676`, revision `1.4.0+34cbb9a40`.
- Supported ABIs are exactly `arm64-v8a` and baseline `x86_64`. Do not advertise 32-bit ABIs.
- Runtime files under `app/src/main/jniLibs/*/libbun_exec.so` are Android PIE executables renamed for package extraction. They are not JNI libraries and must never be loaded with `System.loadLibrary`.
- The executable must run directly from the read-only `nativeLibraryDir`. Never copy an executable into `filesDir`, `cacheDir`, or another writable app directory and execute it there.
- Treat `tools/bun-runtime/runtime.lock.json` as the machine-readable source of truth for release URLs, archive sizes and hashes, binary sizes and hashes, ELF machines, and minimum PT_LOAD alignment.
- Runtime binaries are Git LFS objects. Use `tools/bun-runtime/materialize-runtime.ps1` to reproduce them from official archives and `node tools/bun-runtime/verify-runtime.mjs` to verify checked-in bytes.

Their C source, fixed NDK build and per-ABI bytes are locked in `tools/bun-runtime/supervisor/supervisor.lock.json`; verify with `node tools/bun-runtime/supervisor/verify-supervisor.mjs`. They do not change the official Bun lock or variant.

- Bun is an independent engine, not a Rhino or Node.js alias. The AutoJs6 host routes the standalone `"bun";` directive to this plugin.
- Version 0.1 accepts one immutable JavaScript or TypeScript source snapshot through `ParcelFileDescriptor`.
- Execute with the argument vector equivalent to `bun run --no-install <source>`. Do not invoke a shell, concatenate an untrusted command, or install missing dependencies automatically.
- Contract v1 requests without `workspaceArchiveVersion` transfer one immutable source and do not support relative imports. Requests carrying `workspaceArchiveVersion = 1` transfer one bounded ZIP workspace archive (at most 16384 entries, 64 MiB uncompressed, 16 MiB per file) that `BunWorkspaceArchive` expands into `workspace/project`; the entry point must be a relative `.js/.mjs/.cjs/.jsx/.ts/.mts/.cts/.tsx` file inside it, the project directory becomes the working directory, TMPDIR stays outside it, and only regular files and directories are ever created. Never treat a descriptor as an archive without the key.
- `PluginInfo` advertises `SUPPORTS_WORKSPACE_ARCHIVE`. The AutoJs6 host packs a project only when the script sits below a directory carrying `project.json` or `package.json` (host `BunPluginWorkspaceArchive`); other scripts keep the single-source path. The shared constants live only in `libs/bun-runtime-api.aar` (host build 5280); never copy them into the plugin. Design rationale: `docs/design/m6-workspace-archive.md`.
- `PluginInfo` also advertises `SUPPORTS_HOST_INFO` (M7, first host capability). A request carrying `hostInfoVersion = 1` and the `hostInfo` Bundle (`packageName`, optional advisory `versionDate` / `languageTag`) makes the service verify that the package belongs to the Binder caller UID, resolve the host version through `PackageManager`, write one bounded JSON snapshot (`MAX_HOST_INFO_BYTES`, fixed layout in `BunHostInfoSnapshot`) to `<workspace>/autojs6/host-info.json` (outside `project`, deleted with the run) and export `AUTOJS6_HOST_INFO_FILE`; the terminal Bundle then carries `hostInfoDelivered`. The `AUTOJS6_` environment prefix is reserved for the plugin: reject host requests that use it. Rule failures map to `INVALID_REQUEST` and write failures to `INTERNAL`; never add error codes, AIDL transactions or a child-to-plugin channel for this capability. Advisory fields stay advisory, and the host revokes the snapshot per run (`BunHostCapabilityGrants`). Design rationale: `docs/design/m7-host-capability-bridge.md`.
- `PluginInfo` advertises `SUPPORTS_HOST_CAPABILITY_BRIDGE` (M7, dynamic calls). A request carrying `hostCapabilityBridgeVersion = 1`, the `hostCapabilityBroker` IBinder and the `hostCapabilities` list (1..64 dotted lowercase IDs matching `[a-z][a-z0-9]*(\.[a-z][a-z0-9]*)+`, no duplicates) makes the service open one filesystem unix socket per run under `<cacheDir>/bun-bridge/` (directory 0700, deleted when the run ends) and export `AUTOJS6_HOST_BRIDGE_SOCKET`. The socket speaks bounded HTTP/1.1 (`BunHostBridgeHttp`: one request per connection, `Content-Length` bodies only, 1 KiB request line, 8 KiB headers, 64 KiB body, 5 s idle timeouts): `GET /v1/info` lists the grants and limits, `POST /v1/<capability>` relays one JSON object to the host through the oneway AIDL `IBunHostCapabilityBroker` and waits at most 10 s for the `IBunHostCapabilityCallback` (`BunHostBrokerClient` pins the callback to the host UID and the execution ID). `BunHostBridgeDispatcher` owns the grant check, the 1024-calls-per-run and 4-in-flight limits and the error mapping (INVALID_REQUEST 400, NOT_GRANTED 403, UNKNOWN_CAPABILITY 404, PAYLOAD_TOO_LARGE 413, TOO_MANY_REQUESTS/QUOTA_EXCEEDED 429, HOST_UNAVAILABLE 503, TIMEOUT 504, INTERNAL 500) and never interprets payloads beyond size, UTF-8 validity and the outer braces, so new host capabilities need no plugin change. The terminal Bundle carries `hostBridgeDelivered` and `hostCalls`; bridge errors are JSON replies, never `runScript` error codes. Design rationale: `docs/design/m7-host-capability-bridge-dynamic.md`.
- Bun does not expose AutoJs6 globals, Rhino objects, Android automation APIs, or a Java bridge; the host info snapshot and the bridge capabilities the host grants (`ui.toast`, `device.info`) are the only host capabilities so far. Add future host capabilities only through narrow, versioned, permission-aware contracts, and keep unimplemented Rhino/Node globals failing loudly (`ReferenceError`) instead of shimming them.
- The default timeout is 60 seconds, the maximum source size is 16 MiB, and the maximum combined stdout and stderr streaming budget is 8 MiB. Keep request, argument, environment, and name limits synchronized with `BunRuntimeContract`.
- Send stdout and stderr only as bounded chunks through the oneway callback. The returned terminal Bundle and the `finished` event contain status and diagnostic summaries and must never carry complete output streams, so Binder transactions remain below the platform limit.
- Keep cancellation deterministic: destroy the process, apply the bounded forcible fallback, close descriptors, remove execution state, and clean only the exact private job directory.
- Launch probes and scripts through `SupervisedProcess`: its private control-pipe EOF makes the supervisor send SIGTERM, wait 200 ms, send SIGKILL if needed, and reap its owned immediate Bun child. Do not revert to Android's inherited `Process.destroyForcibly()`, guess a PID, or close output readers before requesting termination. Arbitrary detached descendants are not supervised.
- A Bun child process is isolation for lifecycle and crashes, not a security sandbox. Run scripts as trusted code under the plugin UID.
