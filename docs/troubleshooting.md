# Bun Runtime 排错指南

本文面向通过 AutoJs6 运行单文件 JavaScript / TypeScript 的用户.
正式产品要求 Android 13 (API 33) 或更高版本, 仅提供 `arm64-v8a` 与 baseline `x86_64`.
实验运行时的某组测试通过, 不表示正式 APK 的系统下限或发布状态已经改变.
版本与实验进展见 [Roadmap](../ROADMAP.md); 功能说明见 [README](../README.md).

## 先用一个最小脚本确定问题发生在哪一步

在 AutoJs6 中新建一个文件, 使用英文引号和分号, 将引擎指令放在第一行:

```javascript
"bun";
console.log("Bun is running", Bun.version);
```

先保存并运行这一文件. 它不需要依赖、网络、自动化权限或其他项目文件.
如果它成功, 再逐步加入原脚本的导入、文件操作和网络请求, 找出第一个失败的步骤.
如果它失败, 按下表检查宿主识别、安装和运行环境, 保留完整错误文字.

## 按症状检查

| 症状 | 常见原因 | 处理方式 |
|---|---|---|
| `"bun";` 没有选择 Bun, 或 `Bun` 未定义 | 指令位置/引号不正确, 或 AutoJs6 版本不支持本插件契约 | 将上面的最小脚本原样单独运行. 核对宿主 build 至少为 5278, 并检查宿主是否识别 Bun Runtime |
| 找不到插件, 插件未激活, 或绑定服务失败 | 插件未安装、被禁用, 宿主与插件版本不匹配, 或权限/签名检查未通过 | 确认安装的是本项目的 Bun Runtime, 在宿主检查插件状态, 重新发起运行. 使用配套的正式宿主和插件; 保留权限错误文字, 不通过修改包名或绕过服务权限解决 |
| APK 无法安装, 提示 ABI 不匹配 | 安装了不同 CPU 架构的单 ABI 包 | 大多数手机/平板选择 `arm64-v8a`; x86_64 设备/AVD 选择 `x86_64`. `universal` 包含两者, 但不能让 32 位设备运行 64 位引擎 |
| 系统版本过低, 或 Android 12L 及更早系统出现 SIGSYS | 官方 Bun 使用了该系统应用 seccomp 策略不允许的 syscall | 正式插件需要 API 33+. 修改 APK 的 minSdk 或复制可执行文件不会补齐 syscall 支持. 查看 Roadmap 中独立实验线的具体证据 |
| 在 16 KiB 页的 x86_64 环境启动失败 | 官方 x86_64 runtime 仍有已知页大小限制 | 保留设备/API/ABI/页大小和退出信息. 原生 ARM64 的开发版测试及独立 JSC 候选不能代替当前 Release APK 的验收 |
| 运行超时 | 无限循环、未结束的异步任务, 或任务超过请求的时间上限 | 默认超时为 60 秒. 先让最小任务正常结束, 再检查循环、timer、等待条件和网络截止时间, 必要时拆分任务 |
| 输出只出现一部分, 随后报输出超限 | stdout 与 stderr 合计超过输出预算 | 默认合并上限为 8 MiB. 减少循环打印、巨大对象或二进制内容, 输出计数和摘要. 输出超限会以错误结束运行, 并非成功后静默截断 |
| 提交源码时被拒绝 | 单次源码快照超过上限, 或请求参数无效 | 源码上限为 16 MiB, 以 UTF-8 字节数计算. 缩小脚本, 检查宿主所给参数和错误文字; 这与 stdout/stderr 的 8 MiB 上限不同 |
| npm 包找不到 | 插件以 `bun run --no-install <source>` 执行, 不会安装依赖或传输 node_modules | 对可打包的纯 JS 依赖, 先在电脑上生成一个适用于 Bun 的单文件产物. 在设备上运行前检查它是否仍含外部包导入. native addon 不能靠这种打包方式变成可用 |
| `import './utils.js'` 找不到文件 | 插件只接收当前文件快照, 不接收项目目录 | 在电脑上把需要的模块合并为单文件, 检查产物不再依赖相对工程导入. 单文件内 ESM 语法本身可用 |
| `click()`、`toast()`、Rhino 对象或 Java 类不可用 | Bun 是独立引擎, 当前没有 AutoJs6 globals 或 Java bridge | 将这类自动化/Java 操作保留在宿主支持的引擎侧. Bun 脚本仅使用实际提供的 Bun/JavaScript 能力; 能力桥仍是 Roadmap 的后续工作 |
| 取消后仍看到进程, 或后续脚本无法启动 | 生命周期清理异常, 或脚本创建了脱离监督范围的后代 | 记录取消时间、终态和最小复现. 当前 supervisor 负责其直接 Bun 子进程, 不管理任意 detached 后代. 不要按猜测 PID 批量杀进程 |

## 读懂终态和诊断

`Bun execution timed out`、`Bun output exceeded the configured byte limit` 和
`Bun execution was cancelled` 分别表示超时、输出超限和取消. 它们属于不同的终止原因.
`Bun exited with code ...` 表示运行进程异常结束, 需要结合 stderr 和设备环境判断.
单凭一个非零退出码不能确定具体 syscall; 应用/系统崩溃也不能自动归因到 Bun 的同一处代码.

宿主接收的 stdout/stderr 是持续发送的有界片段. terminal Bundle 和 `finished` 事件只提供
状态及诊断摘要, 不包含全部输出. 接口调用者需要在回调中按顺序收集片段, 并处理终态;
不要只查看最后一个返回值来判断脚本是否输出过内容.

超时、取消和输出超限会触发有界终止与直接子进程回收. 如果存在退出码、reaped 或工作目录
清理诊断, 请一并保留. 插件进程隔离用于生命周期和崩溃处理, 不是不可信脚本的安全沙箱;
脚本以插件 UID 执行.

## 报告问题时提供什么

请提供能复现的最小脚本, 以及下列信息:

- AutoJs6 版本/build、Bun Runtime 安装版本与 APK ABI 类型.
- 设备型号、Android 版本与实际 API; 如已知, 提供页大小和是否使用 native bridge.
- 完整错误文字、退出码、运行到失败的大致时间, 是首次运行还是重复绑定/重启后出现.
- 是否涉及导入、网络、spawn、取消或大量输出; 最小脚本是否也失败.
- 若是某个实验候选, 给出对应报告/提交或 APK 摘要, 避免混淆不同 native 字节的结果.

不要发送签名密钥、令牌、完整私有工程或与复现无关的设备日志. 如果必须提供日志,
保留与该次运行对应的有界片段并移除敏感数据. 构建维护者还应记录实际 APK 与源码绑定;
仅报告 "最新版" 或借用另一台设备的成功记录不足以定位问题.

## 实验范围与后续进展

官方 API 33+ 产品、API 28 实验线和独立大页 JSC 候选分别记录证据. 当前单源码、
no-install、无相对工程导入、无 AutoJs6 globals/Java bridge 的契约不变.
实验候选 `distributionReady=false` 时, 不能把其测试通过表述为已发布正式支持.
也不要将对齐检查、ARM64 翻译运行、原生 ARM64 硬件页和 x86 模拟页 ABI 混为一个结论.

继续开发前阅读 [会话交接](SESSION_HANDOFF.md); 具体设备批次见
[兼容性证据目录](compatibility/). 历史失败报告保留原样, 后续修复另立记录.
