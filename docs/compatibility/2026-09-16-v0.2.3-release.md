## 验收范围 (每轮 10 组, force-stop 前后各一轮)

1. environment, installed final APK, extracted runtime and supervisor integrity
2. signature permission, Wake discovery and activation
3. action/category discovery, explicit Binder, PluginInfo capabilities and repeated prewarm
4. JavaScript, TypeScript, Unicode and bounded streaming callbacks
5. all five checked-in samples including local HTTP fetch and file I/O
6. workspace archive project round trip, hostile archive and missing entry rejection
7. supervised timeout and output-limit reaping, localized summary and invalid request rejection
8. cancellation after readiness, supervised reaping and recovery
9. host info snapshot delivered only when offered, attributed to the caller UID, spoofed packages and hostile requests fail closed
10. unbind and reconnect

探针是纯 Android/Java `Instrumentation`, 以 release 变体 androidTest APK 编译并使用 release 签名, 从主 APK 之外持有插件签名权限, 直接驱动生产 Binder;
每轮开始前硬断言 API 级别, 页大小, 安装版本, 安装后 base.apk SHA-256, 期望 ABI 集合以及 `nativeLibraryDir` 中运行时/监督器的 SHA-256 与字节数.
装有 AutoJs6 的三台真机使用私有权限名的探针 (AutoJs6 拥有 `org.autojs.permission.PLUGIN`), AVD 与 Samsung 使用 AutoJs6 权限名的探针; 两者源码相同, 只有权限名不同.
第 9 组是本次新增: 不带请求键时脚本看不到快照且 `AUTOJS6_*` 为空; 带 `hostInfoVersion = 1` 与包名时 `hostInfoDelivered=true`, 脚本从 `AUTOJS6_HOST_INFO_FILE` 读到 16 个字段 (宿主包名/版本名/版本号由插件经 PackageManager 解析, `versionDate` 去除首尾空白, 插件包名/版本/运行时 `1.4.0+34cbb9a40`/ABI, 源文件名, `workspaceArchive=false`, 文件位于 `autojs6/host-info.json`);
探针自身的 instrumentation 包名 (独立 UID) 与 `org.autojs.autojs6` 作为冒充包名, 未知快照版本 `2`, 以及请求环境里的 `AUTOJS6_HOST_INFO_FILE` 均在 Bun 启动前被拒为 INVALID_REQUEST, 随后不带请求键的单源码执行不受影响.

## 生命周期, M6 与 M7 证据 (每台设备每轮均出现)

- `LIFECYCLE error=TIMEOUT|OUTPUT_LIMIT|CANCELLED childPid=... reaped=true exitCode=137 workspaceRemoved=true`: 三种终止均由监督器 SIGKILL 并回收, 每次运行的私有工作区随之删除.
- `TIMEOUT_SUMMARY` 与 `HOSTILE_ARCHIVE`: 摘要按设备语言本地化 (Xiaomi 为中文, 其余为英文), 与十语言资源一致.
- `WORKSPACE files=3 bytes=549 root=.../cache/bun-executions/<run>/project`: 归档展开到私有工作区后以项目目录为工作目录执行, 相对 import 与 JSON import 成功; 含 `../` 的归档与缺失入口被拒绝.
- `HOST_INFO 1|<插件包名>|0.2.3|8|Sep 16, 2026|zh-Hans-CN|<插件包名>|0.2.3|8|1.4.0|1.4.0+34cbb9a40|<ABI>|host-info.js|false|true|AUTOJS6_HOST_INFO_FILE`: 五个环境的快照字段除 ABI (四台 arm64-v8a, AVD x86_64) 外逐字相同.

## 过程说明

- 第一轮验收在 90851a7 字节上执行: 五个环境 1-8 组全部通过, 新增的宿主信息组失败于 `started event expectation true: [finished]`. 原因在探针而非插件: 探针作为 instrumentation 运行在插件进程 UID 内, `getPackagesForUid(callingUid)` 只含插件包, 探针把自己的 instrumentation 包名 (独立 UID) 作为宿主包名提供, 被插件按设计拒为 INVALID_REQUEST. 探针改为提供插件包名并断言自身包名被拒, 插件代码未改.
- 发布说明生成器仍是 v0.2.2 措辞 (16 KiB 签名验收 "未重复", 无宿主信息段落), 由 d265c2a 更正. AGP 会把提交号写进 APK 的 `META-INF/version-control-info.textproto`, 因此 APK 重建, 注释标签 `v0.2.3` 从 90851a7 移到 d265c2a (当时尚无 Release), 五个环境在最终字节上全部重跑; 90851a7 上的两轮验收作为作废证据保存在本地 `.git/release-acceptance-v023-20260916-90851a7-superseded/`, 不计入本报告.
- 构建脚本 `%TEMP%/release-build-20260916.sh` 三次 Gradle (release APK/单测 45/45/lint, 两种探针), 驱动 `.git/release-v023-acceptance-20260916.mjs` (十组), 记录 `.git/release-acceptance-v023-20260916/`; 资产 `node .git/release-v023-20260916.mjs assemble|verify|preflight|publish`, 目录 `E:/.wsl/release-assets/autojs6-plugin-bun-runtime-v0.2.3-d265c2a`, 13 个资产一次上传成功.

## 边界

- The user-facing upgrade path exercised is v0.2.2 to v0.2.3 on two devices reset to the published v0.2.2 APKs; v0.2.0 to v0.2.3 was not exercised (v0.2.0 to v0.2.2 was exercised for the previous Release).
- The native arm64 16 KiB acceptance (Samsung SM-A566B, API 36, Remote Test Lab) is a fresh install of the arm64-v8a bytes; it is not an upgrade path and the universal APK was not repeated on 16 KiB hardware.
- Native x86_64 large-page execution remains blocked; the x86_64 signed acceptance ran on a 4 KiB API 33 AVD.
- The black-box probe holds the plugin signature permission and drives the production Binder directly; it is not an AutoJs6 host round trip. The workspace archive group packs its own ZIP, and the host info group offers the plugin's own package because the probe runs inside the plugin's process UID; the cross-UID path (a separate host package checked against its own calling UID) is covered only by the M7 host round trips with a locally built AutoJs6 (docs/compatibility/2026-09-16-m7-host-info-snapshot.md). No released AutoJs6 sends project archives or offers the snapshot yet.
- The probe is compiled twice from the same source: devices carrying AutoJs6 (which owns org.autojs.permission.PLUGIN) use a private permission name, the AVD and the Samsung probes use the AutoJs6 permission name.
- Official-source publication does not count as publication of patched APK/source assets.
