## 固定实验和观测含义

源码提交 `e07058d210f15aa6ac3f9350f7393b9dc6dcfb6e`. 新资产和 instrumentation 仅加入
opt-in JSC 测试源集, 通过真实生产服务、原 AAR 和 supervisor 执行. 原七模式压力、
前一 sampling 资产/Java/语义校验器、原八项 Binder 和35探针均未修改或重新计分.

每轮按固定顺序运行两个独立 Bun 进程:

- `target`: 每次调用原 `jscPressureHotLoop`, 对照独立 BigInt 结果; 即使第一段已达到
  三个 DFG 帧, 也继续执行全部四段.
- `target-absent`: profile 内改为调用独立命名的相同算术控制函数, 原目标只在 profile 前预热.
  捕获期间目标调用数明确为0. 这是人为构造的目标缺席, 不能称为自然采样不足的复现.

目标仍有128次预热、`noFTL` 和一次优化请求. 控制函数也有 `noFTL`, 没有额外预热或优化请求.
固定四个一次调用的命名回调 `jscRestartPhase1..4`, 每段300ms/100000调用上限,
采样间隔1000微秒. 源码16KiB、输出64KiB、测量工作阶段20秒、Binder25秒上限不变.
没有新增 JIT 选项、`noInline`、等待或依赖. 新命名回调和观测逻辑仍可能扰动优化与调度.

每段保存调用数、callback/profile时长、编译/重优化计数、trace/frame及目标/控制/全部层级统计,
最多16个名称/category直方图项与溢出数, 当前阶段证人和至多三个目标DFG证人.
`restartObserved`要求每段都有本段名称、没有其他段名称, 且四段时间区间有序不重叠.
它是有界外部观测, 不是 profiler 线程身份或每个内部状态的直接证明.

诊断先输出完整记录, 再由累计目标DFG数、编译状态、无目标FTL及不同证人时间戳决定exit0/1.
instrumentation分别核对进程退出、Binder succeeded/错误码、输出和工作目录清理;
归档重新核对原始文本与结构化字段. 收集完成、目标门槛、阶段观测、目标缺席对照是独立结果.
空/陈旧数据可以保留为观测false, 超时、异常、输出漂移或清理失败不能冒充完整收集.

两台设备均为API36原生x86_64, 两轮之间停止实验服务并检查执行UID无进程.
每轮固定两模式, 没有失败尝试或额外重试. 表中数字为各段目标DFG帧:

| 4096 | 2 | 69 / 103 / 118 / 0 | 0 / 0 / 0 / 0 | 两模式均true | 0 / 1 |
| 16384 | 1 | 87 / 90 / 113 / 125 | 0 / 0 / 0 / 0 | 两模式均true | 0 / 1 |
| 16384 | 2 | 115 / 91 / 100 / 127 | 0 / 0 / 0 / 0 | 两模式均true | 0 / 1 |

四次正常模式均满足累计目标门槛. 四次缺席对照的每段都有控制函数采样而没有目标帧,
`absentControlObserved=true`, 累计目标门槛false且实际exit1. 这验证了真实设备的失败结果保留路径,
并未把有意缺席改成运行成功或把它算作历史低样本故障.

4KiB第二轮正常模式提供了此前没有的单段现象:

第四段仍执行目标工作, profiler仍采到当前阶段; 该段目标的全部已知/未知层级帧均为0,
直方图无溢出. 第三段目标栈顶帧消失的同时, 调用者从DFG样本转为FTL样本.
第三段时间戳78.862835866至79.159012356, 第四段79.165923696至79.466193461,
没有跨段重用旧样本. 第四段的125个 `runWork` DFG帧和125个当前阶段LLInt帧也保留.

这缩小了调查范围: **目标帧消失与调用者FTL相关联, 采样器在该段仍然工作**.
固定源码表明 `noFTL`不禁止内联, FTL PC映射另受VM开关控制, 恢复出的内联帧使用机器代码的tier.
但本次没有捕获实际内联图、PC映射对象或开关状态, 不能确定内联/映射就是原因.
原2<3失败没有逐段信息, 且本轮正常模式已在前段通过累计门槛, 两者不能直接等同.
