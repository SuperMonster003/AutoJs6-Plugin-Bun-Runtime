## 验收范围 (每轮 11 组, force-stop 前后各一轮)

1. environment, installed final APK, extracted runtime and supervisor integrity
2. signature permission, Wake discovery and activation
3. action/category discovery, explicit Binder, PluginInfo capabilities and repeated prewarm
4. JavaScript, TypeScript, Unicode and bounded streaming callbacks
5. all five checked-in samples including local HTTP fetch and file I/O
6. workspace archive project round trip, hostile archive and missing entry rejection
7. supervised timeout and output-limit reaping, localized summary and invalid request rejection
8. cancellation after readiness, supervised reaping and recovery
9. host info snapshot delivered only when offered, attributed to the caller UID, spoofed packages and hostile requests fail closed
10. dynamic capability bridge relays granted calls to the request's broker, refuses ungranted and malformed calls, counts relays and fails closed
11. unbind and reconnect

探针是纯 Android/Java `Instrumentation`, 以 release 变体 androidTest APK 编译并使用 release 签名, 从主 APK 之外持有插件签名权限, 直接驱动生产 Binder;
每轮开始前硬断言 API 级别, 页大小, 安装版本, 安装后 base.apk SHA-256, 期望 ABI 集合以及 `nativeLibraryDir` 中运行时/监督器的 SHA-256 与字节数.
装有 AutoJs6 的三台真机使用私有权限名的探针 (`5780bf90`, AutoJs6 拥有 `org.autojs.permission.PLUGIN`), AVD 使用 AutoJs6 权限名的探针 (`934b88d3`); 两者源码相同, 只有权限名不同.
第 10 组是本次新增 (解绑与重连顺延为第 11 组): 不带请求键时脚本看不到 `AUTOJS6_HOST_BRIDGE_SOCKET`, 终态 Bundle 里也没有 `hostBridgeDelivered` / `hostCalls`; 带 `hostCapabilityBridgeVersion = 1`, 一个进程内的 `IBunHostCapabilityBroker` 与授权 ID `ui.toast` / `device.info` 时, 脚本经 `fetch(url, { unix })` 读到 `GET /v1/info` 的信息文档 (`bridgeVersion` 1, 两个能力, 64 KiB / 256 KiB / 1024 次 / 4 路 / 10 s 的限额),
`device.info` 与 `ui.toast` 按顺序中继到 broker 并原样回显请求体 (200), 未授权的 `net.http` 被拒为 403 `NOT_GRANTED`, 无点号的能力 ID 与数组请求体在 broker 看到之前就被拒为 400 `INVALID_REQUEST`, 终态 `hostCalls = 2`;
未知桥版本, 缺失 broker 与无点号的授权 ID 均在 Bun 启动前被拒为 INVALID_REQUEST, 随后不带请求键的单源码执行不受影响.

## 生命周期, M6 与 M7 证据 (每台设备每轮均出现)

- `LIFECYCLE error=TIMEOUT|OUTPUT_LIMIT|CANCELLED childPid=... reaped=true exitCode=137 workspaceRemoved=true`: 三种终止均由监督器 SIGKILL 并回收, 每次运行的私有工作区随之删除.
- `TIMEOUT_SUMMARY` 与 `HOSTILE_ARCHIVE`: 摘要按设备语言本地化 (Xiaomi 为中文, 其余为英文), 与十语言资源一致.
- `WORKSPACE files=3 bytes=549 root=.../cache/bun-executions/<run>/project`: 归档展开到私有工作区后以项目目录为工作目录执行, 相对 import 与 JSON import 成功; 含 `../` 的归档与缺失入口被拒绝.
- `HOST_INFO 1|<插件包名>|0.2.4|112|Sep 16, 2026|zh-Hans-CN|<插件包名>|0.2.4|112|1.4.0|1.4.0+34cbb9a40|<ABI>|host-info.js|false|true|AUTOJS6_HOST_INFO_FILE`: 四个环境的快照字段除 ABI (三台 arm64-v8a, AVD x86_64) 外逐字相同.

## 边界

- The user-facing upgrade path exercised is v0.2.3 to v0.2.4 on two devices; v0.2.2 to v0.2.4 was not exercised (v0.2.2 to v0.2.3 was exercised for the previous Release).
- No 16 KiB environment this time: the Samsung SM-A566B Remote Test Lab device was not available, and the only 16 KiB image at hand (x86_64 API 37 emulator) cannot run the official x86_64 Bun at all (JavaScriptCore 4 KiB page limit, refusal reproduced on request and recorded above). The Bun runtime and supervisor payloads are byte-identical to v0.2.2 and v0.2.3, whose signed arm64-v8a APKs passed on the Samsung; that evidence is not repeated on the v0.2.4 bytes.
- Native x86_64 large-page execution remains blocked; the x86_64 signed acceptance ran on a 4 KiB API 33 AVD.
- The black-box probe holds the plugin signature permission and drives the production Binder directly; it is not an AutoJs6 host round trip. The bridge group hands over a broker living in the plugin's own process UID, so callback attribution across UIDs and the real ui.toast / device.info host implementations are covered only by the M7 host round trips with a locally built AutoJs6 (docs/compatibility/2026-09-16-m7-host-capability-bridge.md). No released AutoJs6 sends project archives, offers the snapshot or the bridge yet.
- The probe is compiled twice from the same source: devices carrying AutoJs6 (which owns org.autojs.permission.PLUGIN) use a private permission name, the AVD probe uses the AutoJs6 permission name.
- Official-source publication does not count as publication of patched APK/source assets.
