# M5: 原生 x86_64 16 KiB JavaScriptCore 修复候选

证据日期: 2026-09-12. G1/G2, 非官方 payload 替换, 非已发布 Release.

显式大页 JIT 配置重编 pinned WebKit 并重新链接九补丁 Bun 后, 原生 x86_64 的 API 36 / 4 KiB 与 API 36 / 16 KiB AVD 均通过现有完整 8 项 Binder 套件两轮, **32/32**. 启动不再出现旧 `CeilingOnPageSize` 中止. [原始机器报告](2026-09-12-m5-x86-16k-jsc-binder.json) 记录两个环境相同的 APK/payload 摘要、完整输出、进程重启和卸载后零 UID 进程.

| 对照 | 页大小 | APK SHA-256 | 结果 |
|---|---:|---|---|
| AVD_API_36.1, native x86_64, API 36 | 4096 | `bb224e2a5fbecaf271fe2a8f4912eef4739a96c97b1075d36c0d643e934e74f8` | 8/8 + 8/8 |
| aj6-ps16k-36-x86_64, native x86_64, API 36 | 16384 | 同上 | 8/8 + 8/8 |

两个 AVD 都可提供 ARM 翻译桥, 但这里安装的是 x86_64-only APK, 校验为 x86 ELF, primary ABI 和 kernel 都是 x86_64. 因此这不是旧的 translated ARM64 结果. 4 KiB 和 16 KiB 两者分别硬断言实际页大小, 不靠 AVD 名称推断.

随后以清洁构建 Bun 打包、合入最终生成文档和工具输入绑定后, 两个环境再次各两轮 8/8. [最终工具与清洁产物复测](2026-09-12-m5-x86-16k-final-binder.json) 另存新的 APK/source 绑定, 两个 APK 的 v2 签名验证、安装后主包/测试包 SHA-256 及卸载后零 UID 进程全部通过. 原生 payload 哈希不变, 不将重复复测累加为新的环境. 两台 AVD 已关闭, 没有留下测试包.

## 配置与因果关系

固定 Bun head 为 `7b9ac266888abda7ee6ec0b8ac11a74236420030`, WebKit 为 `0f966e81b78c84bb23213e391bc679c4ef83e56b`. 原 [PageBlock.h](https://github.com/oven-sh/WebKit/blob/0f966e81b78c84bb23213e391bc679c4ef83e56b/Source/WTF/wtf/PageBlock.h) 的编译期页大小上限是先前定位的阻断; 运行时关闭 JIT 不能改变该已编译常量. 本次不再修改 WebKit 源码, 而是显式设定:

```text
USE_64KB_PAGE_BLOCK=1
ENABLE_JIT=1, ENABLE_DFG_JIT=1, ENABLE_FTL_JIT=1, ENABLE_C_LOOP=0
ENABLE_SAMPLING_PROFILER=1
USE_MIMALLOC=1, USE_EXTERNAL_MIMALLOC=1
USE_SYSTEM_MALLOC=0, USE_ISO_MALLOC=1
ENABLE_WEBASSEMBLY=1, ENABLE_WEBASSEMBLY_BBQJIT=1, ENABLE_WEBASSEMBLY_OMGJIT=1
```

配置与 Bun 的外部 mimalloc 集成保持一致. Android API 28, baseline Nehalem/no-AVX, NDK r27c, Clang 21.1.5, 固定 Docker image 和离线输入仍受约束. 重建 JSC/WTF/bmalloc 三个静态库及 generated config, 上游同一锁定 Android x86 WebKit 归档中的 ICU 与其他头文件复用, **没有声称 ICU 也重新构建**. 编译启用 JIT/DFG/FTL/Wasm JIT 不等于各层优化器、全部 Wasm 或性能矩阵已逐项验收; 64 KiB 编译上限也不等于已经测试 64 KiB Android.

候选 Bun 为 90609480 bytes, SHA-256 `704cc15634da42bbea46cbced53a4e3fd719ed9f88ce78bb975ee89113963e38`, ELF64 x86_64 PIE, minimum PT_LOAD alignment=16384, 无 W+X load 或 executable stack. [独立 candidate lock](../../tools/bun-runtime/experimental/webkit-x86_64-16k/candidate.lock.json) 绑定配置、静态库、recipe 和 ELF. APK 中 executable 仍只从安装后的 `nativeLibraryDir` 执行.

## 重建与门禁

首次 Binder 候选来自专用副本中重新编译 Bun C/C++ 并重新链接; 原始九补丁双轮构建与官方 payload 未改动. 锁中保留 `diagnostic-incremental` 的最初来源, 不能因后来复测而改写来源. 随后两个全新 WebKit 构建目录的三个静态库和 config 逐字节一致, 两个全新九补丁 Bun checkout 又分别完成全部 native/Rust 清洁构建, **两次完整 Bun SHA-256 也都等于上述 Binder 已测候选**. [独立清洁重建证据](2026-09-12-m5-x86-16k-clean-builds.json) 绑定两组库、config、Bun 产物、完整离线 preflight receipt 与 recipe, 不由局部静态库一致性推断整包结果.

[构建说明](../../tools/bun-runtime/experimental/webkit-x86_64-16k/README.md) 提供大页配置和干净 Bun 构建流程. 初次 clean-build 接线失败分别是旧 Cargo 缓存缺少 build-std crate, 以及 WebKit bundle 尚未通过 Ninja 解包就复制文件; 后续使用完整锁定缓存、先运行官方 offline `WebKit` target, 并从新 checkout 重跑, 不绕过输入验证或在旧输出上冒称清洁构建.

正式 APK 仍包含官方 `1.4.0+34cbb9a40`, 正式 x86_64 的 >4096-byte 页保护不变. 新候选仅在独立 test-only `.api28binder.jsc16k` 包启用 65536 编译上限, source lock 和 `distributionReady=false` 与生产发行线分离. 剩余 syscall/FD/API 边界、大页 JIT 压力/性能、对应源码发行集与最终签名 Release APK 验收仍须完成. 不能据此宣称官方 x86_64 或一般端到端 16 KiB 支持已经发布.
