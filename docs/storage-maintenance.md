# 开发环境磁盘维护

本项目的独立 native 构建和设备回归会产生多份源码检出、编译缓存、APK 和 AVD.
清理时应保留能核验历史结论的材料, 先移除已完成任务的可重建中间产物.
本指南面向开发环境维护, 不改变运行时支持范围或发布门禁.

## 先确认任务和保留材料

从 [会话交接](SESSION_HANDOFF.md) 找到当前源码、构建、设备任务和本机记录.
检查 Git 状态、worktree 清单、Windows/WSL 进程、Docker 容器、AVD 名称及端口,
确认精确目标没有活动构建或设备任务. 其他任务新启动的模拟器可以继续运行;
判断依据是名称、进程和路径, 不能只看某一次 ADB 清单是否为空.

| 材料 | 处理原则 |
|---|---|
| 已验收和失败批次的 APK、原始输出、driver exit、安装/UID 清理记录 | 保留原字节和原路径; 目录名含 `tmp` 或 `build-cache` 不能作为删除依据 |
| 独立构建的完整 Bun、`bun-profile`、map、Ninja/CMake 日志和构建 receipt | 保留每轮文件, 清理前后核对完整 SHA-256 |
| Bun/WebKit Git 对象、补丁、源码输入锁、对应源码包 | 保留, 包括当前诊断涉及的历史源码 |
| 两套独立 JSC 库/config、原 ICU、固定 NDK/工具链/输入包、锁定 Docker image | 保留, 后续重现或重链接仍需使用 |
| 已结束的 Bun checkout 内 `build/autojs6-api28/cache` | 在确认没有活动构建且成品/日志完整后, 可按精确目录清理 |
| 已结束构建的 ABI 子目录内 `obj`、`pch`、`rust-target` | 可清理的编译中间产物; 保留该 ABI 目录下的完整成品、符号、map、配置和日志 |
| 已退役的项目专用 AVD | 先保存 `.ini` 和内部配置, 核对原套件归档及包清理记录, 再删除该实例与对应 `.ini` |
| 当前诊断用 AVD、通用 AVD、其他项目容器/缓存 | 保留; 不因缺少活动进程就推断其中没有用户数据 |
| 已失效的 Gradle 修复备份 | 核对后续构建成功和修复 receipt 后单独处理; 当前使用的 Gradle 缓存不属于同一目标 |

不能用全盘递归清理、`git clean -fdx`、删除整个临时根目录或无筛选的 Docker prune
代替上述核对. Windows 删除前检查解析后的绝对路径和 reparse point, 使用同一
PowerShell 会话的 `Remove-Item -LiteralPath`; WSL 内部文件在该发行版内操作.

## 记录清理及其后续影响

清理清单至少包含精确目标、来源/任务、文件数、逻辑与实际占用、保留文件的摘要,
以及操作退出码和前后磁盘空间. 多阶段操作逐项落盘, 中断后先读 receipt,
不要重跑已经完成的删除脚本. 原失败和拒绝记录也应保留.

删除编译缓存和目标文件后, 历史构建的退出码、成品及原始证据仍可核验,
但这些目录已经不再具备当时完整的增量构建状态. 不应再次运行 Ninja 并把新结果
当作历史 no-work 检查, 也不要为恢复缓存启动重复的 clean build.
确需新构建时创建新的独立目录和证据批次.

保留退役 AVD 使用的 SDK system image, 配置备份可用于重新创建同种环境.
重建实例会产生新的用户数据和 UID; 重新核对实际 API/ABI/页大小后另建设备批次,
不能从旧实例的历史成绩直接推导新实例通过.

## WSL 内部释放与 Windows 实际释放

分别记录 Linux `df` 的已用/可用空间、VHDX 文件大小和 Windows 卷的剩余空间.
WSL 的虚拟容量上限不是宿主磁盘的剩余容量; 动态 VHD 删除内部文件后也未必
自动缩小. 参见 [Microsoft WSL 磁盘说明](https://learn.microsoft.com/en-us/windows/wsl/disk-space).

对确认的发行版文件系统执行 TRIM 可以通知底层哪些块已经空闲. `fstrim` 报告的
discard 字节数可能包含早已空闲的空间, 不能当作本轮新释放量或 Windows 增量.
使用已核对的完整程序路径, 保留实际退出码, 再复测宿主空间.

若宿主文件仍未缩小, 后续可在保存并关闭 WSL 工作后, 从管理员终端进行离线
`compact vdisk`. 先按发行版注册信息核对 VHDX 的唯一绝对路径, 确认发行版已停止,
只选择该文件并执行 compact, 保存日志与前后大小.
[Microsoft 的 compact vdisk 说明](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/compact-vdisk)
要求目标是已分离或以只读方式挂载的动态 VHD. 有活动 IDE/容器连接时先安排停机窗口;
不要为了统计空间中断其他任务, 不使用注销发行版或重建文件系统来代替压缩.
